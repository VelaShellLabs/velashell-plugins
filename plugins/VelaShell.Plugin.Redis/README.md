# VelaShell Redis 插件

Redis / Valkey 的完整界面客户端。以**工作台连接类型**(`contributes.workspaces`)接入宿主 ——
在连接配置页里与 SSH/SFTP/FTP 同为一等公民,而连接对话框、凭据加密落盘、登录弹窗、
云同步、会话树与最近连接全部由宿主复用。

设计与取舍见 [Redis 客户端插件化调研与设计](https://github.com/VelaShellLabs/velashell-docs/blob/main/zh/host/Redis客户端插件化调研与设计.md)。

## 一、它是什么形状

一个停靠文档,左右分栏 + 底部抽屉:

```
┌ 文档头 36px:● 名称 · 端点 ↝ 跳板机 · [db0 ▾] 1.2M 个键 · [只读] · [生产]  [自动刷新 5s][导入][导出] ┐
├ 左 420px 可拖 ────────────┬ 右:键详情 ────────────────────────────────────────────────────────────┤
│ ⌕ 过滤 + 前缀/包含/通配   │ 键名 · 类型 · TTL · 规模  [★][复制键名][生成命令][重载][删除 UNLINK]  │
│ → 回显真正要发的命令      │ encoding · 字段数 · MEMORY USAGE · 空闲                                │
│ ★ 收藏下拉 / 面包屑       │ 改 TTL(带实时换算回显) / 重命名(RENAMENX)                          │
├ 工具条 30px ──────────────┤ 解码链:视图[文本|JSON|转义|Hex] 解压[…] 反序列化[…]   链可逆 · 可写回 │
│ [新建键][重扫][多选][收藏]│ ⌕ 成员内过滤 · 排序 · [分数区间 下界 上界] · [◀][▶][每页 200 ▾]        │
│ 列头 26px / 键行 28px     ├────────────────────────────────────────────────────────────────────────┤
│ 键列表(扁平 + 分组行)    │ 值编辑器 或 成员表(# / 字段 / 值 / 字节;zset 换成 排名/成员/分数/差值)│
│ 批量条:已选 N 个键 …     │ 成员编辑条 + 新增条                                                    │
│ ▬▬▬▭ 已扫 41 208 · 游标…  │ [保存][格式化][复制值][下载为文件] · 游标状态 · 截断与精度说明          │
├───────────────────────────┴────────────────────────────────────────────────────────────────────────┤
│ 状态条 24px:扫描进度(诚实措辞)· 错误:无 · RESP3 · 7.2.4 · 12 ms                                 │
├────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 控制台 │ 概览 │ 慢日志 │ 客户端 │ 订阅 │ 监视 MONITOR │ 集群 │ 内存分析          Ctrl+` ⌄ 收起抽屉 │
└────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

四件事(翻键、改值、敲命令、看服务器状态)是**并行**的,所以不做成互斥的顶层页签。
抽屉这个形状也是本应用用户最熟的:内容在上,命令行在下。

面板上还有三个**贴在本面板内**的覆盖层(不是飘在屏幕中央的系统弹窗):确认闸门、
新建键、导入 / 导出。理由同一条 —— 同时开着生产与开发两个标签页时,一个不说清
「是哪条连接」的弹窗是危险的。

**两处可拖**,写法都与宿主一致(`MainWindow` / `SidebarView` 同款:**5px 透明抓取区画成 1px 细线**):

| 位置 | 怎么实现 |
|---|---|
| 左右分栏 | `GridSplitter` 直接改相邻两列 —— 键名长短因项目而异,固定宽度总有一半人嫌窄一半嫌宽 |
| 抽屉上边缘 | **不用 `GridSplitter`**:它只认紧邻的两个行定义,而抽屉与主体之间隔着状态条和页签条两行固定高度,拖出来的会是那两行变形。这里让抽屉那一行是 `Auto`、主体是 `*`,拖拽条是个 `Thumb`,拖动只改 `DrawerHeight` 一个数,主体自动让位。上界按**当前面板高度**算(给主体留 220px),而不是写死 |

版式(三百多行样式)单放在 `Ui/RedisPanelStyles.axaml`:面板视图必须先有一条活连接才建得起来,
而样式表是个独立的 avares 资源,于是「样式写坏了没有」可以脱离 Redis 单独验(`RedisPanelStylesTests`)。

## 二、几条不肯让步的纪律

| 纪律 | 为什么 |
|---|---|
| **永不 `KEYS`** | 它在百万级键上会阻塞整个实例。键总数走 `DBSIZE`,键列表一律 `SCAN` |
| **进度必须诚实** | 只有游标归零才敢说"已扫完";树上的计数是**已扫描到的**,不是总数 |
| **一批一个往返** | `SCAN` 一页 + 流水线 `TYPE`;6.0+ 有 `SCAN TYPE` 时连 `TYPE` 都省掉 |
| **类型过滤在任何版本上都真生效** | 老服务器不认 `SCAN TYPE` 时退回客户端批量 `TYPE` 收窄 —— 界面写着 hash 就只能列 hash |
| **键与值都是二进制安全的** | 显示按 redis-cli 转义(`\xNN`),操作一律用原始字节 |
| **"没配过"与"不支持"是空状态** | 托管 Redis 普遍禁 `CONFIG`/`CLIENT`/`SLOWLOG`/`MEMORY`,当成错误会让概览页一片红 |
| **拿不到的数值留空,不填 0** | `0` 会被读成一个真实的测量值 |
| **解码视图默认只读** | gzip/二进制值被"以文本形状保存"是真会毁数据的一步 |
| **删除优先 `UNLINK`** | `DEL` 一个百万元素的集合会阻塞实例 |
| **`RENAME` 不静默覆盖** | 默认走 `RENAMENX`,目标已存在时问用户 |
| **`CLIENT NO-TOUCH on`**(7.4+) | 一个只读浏览器不该改变被观测对象的 LRU/LFU 统计 |
| **解码链可逆才允许写回** | 解压两个方向都做得到,所以「解压 + 文本/JSON/转义」可编辑;反序列化只做得到读,选上就转只读并写明是哪一步不可逆 |
| **认得出 ≠ 解得开** | 有 `1f 8b` 魔数却解不开的字节不会被标成 GZip;解出**空**也算失败(否则空白编辑框会被读成"这个键是空的") |
| **未内置的解码器留在原地** | Zstd/LZ4/Snappy/Java/Pickle 点不动,悬停说明"需要额外的第三方依赖" —— 藏起来会让人以为这个客户端不认识它们 |
| **自动刷新不重扫键空间** | 它只刷当前抽屉页与选中的键。每 5 秒对生产库发一轮 `SCAN` 是在替用户制造负载,列表还会在眼皮底下乱跳 |
| **自动刷新不碰有未保存编辑的详情页** | 重读会把编辑区重置回服务端的现值 —— 改了一半没保存的内容会被旧值悄悄盖掉,而且盖得毫无痕迹,用户只会以为自己没输进去。有未保存的编辑时跳过这一次重读,并在保存按钮旁写明为什么停着 |
| **已经知道答案就不再问服务器** | 连接时的 `INFO server` 已经报过 `redis_mode`,单机实例上就不必再发 `CLUSTER NODES` 等一句必然的报错;探测到的拒绝也记住一次。异常被吃掉不等于没有代价 —— 它照样是一次往返、一条服务器错误计数、一行没人看得懂的调试日志 |
| **分组行的批量勾选只覆盖已扫到的** | 一条写着 20 481 的分组行底下大部分键还没扫到,让一次点击去删没见过的键是危险的 |
| **首次连接必须大声失败** | `AbortOnConnectFail = true`。设 false 会让 `ConnectAsync` 成功返回一个后台重试中的对象,界面于是画出一个空键树、然后每个操作各自超时。失败在出口翻成 SDK 的 `Protocol*` 四类,宿主据此弹提示框(它不会为这条连接开标签页,不抛就等于什么都没发生) |
| **不把库写给开发者的建议摆给用户** | 连不上时 StackExchange.Redis 会在消息尾巴附一句 "…use abortConnect=false…"。用户没有连接字符串可改,而那恰恰是上一条刻意不采纳的做法 —— 出口处剪掉 |

## 三、安全护栏:按误伤成本分三档

判定依据是服务器自己给的 `COMMAND INFO` **flags**,不是插件里手写的黑名单 ——
手写名单必然漏掉模块命令(`JSON.SET`)、新版本命令与分叉自带的命令。
只有"毁"这一档按名字定死(`FLUSHDB`/`FLUSHALL`/`SHUTDOWN` 的 flags 与普通写命令没区别)。

| 档 | 处置 |
|---|---|
| 写 | **只读模式**拦住(生产标记默认开)。拦住时给"为什么 + 怎么解除",不是灰一个按钮 |
| 危 | 逐次确认。`MONITOR` 那条写明"会显著降低实例吞吐" |
| 毁 | 要求**手打确认串**(端点/库名)。生产标记下默认整条禁用 |

确认框贴在**本面板上**而不是飘在屏幕中央:同时开着生产与开发两个标签页时,
一个不说清"是哪条连接"的弹窗是危险的。

> 文档里也写明:真正的只读靠 ACL(`+@read`)。客户端的只读模式挡的是**手滑**,不是恶意。

## 四、只有长在 SSH 客户端里才做得到的三件事

1. **`Ctrl+P` → 「Redis: 从 SSH 会话探测 Redis」** —— 一次 exec 找监听端口/进程/版本/配置路径,
   经 `RemoteFs` 读 `redis.conf` 取 `requirepass`,然后**提议**一条连接(宿主打开自己的
   新建连接对话框并预填)。零打字:主机名不用抄、端口不用记、密码不用翻配置。
2. **经 SSH 隧道抵达** —— 连接表单里选一条已保存的 SSH 配置,宿主在打开会话**之前**
   建好会话与本地转发,插件收到的已是本地端点。插件一行 SSH 代码不写、一次凭据不见。
3. **与终端并排** —— VelaDock 一拖:左边键列表,右边应用日志的 `tail -f`。
   Electron 客户端不知道你的终端在哪。

## 五、客户端库与它的边界

`StackExchange.Redis`(MIT)。**按用户决策选库而非自研 RESP**;调研阶段的相反倾向与两条路的
账目记在设计文档 §四/§四.1。库的多路复用模型带来两条硬边界:

- **`MONITOR` 与阻塞类命令(`BLPOP` 等)在这条通道上跑不了。** 控制台在**敲下回车之前**
  就把这个结论显示出来,并如实拒绝 —— 不让用户敲下去然后卡住或超时。
- **`MULTI`/`WATCH`/`SUBSCRIBE` 同理**(它们是连接级状态,而复用会把命令派到任意物理连接)。
  Pub/Sub 走库的 `ISubscriber`(它自带一条专用订阅连接),因此**订阅不会干扰浏览**。

## 八、明确不做的

| 项 | 为什么 |
|---|---|
| RDB / AOF 文件解析 | 那是离线取证工具的活,与"连上活实例操作它"是两种产品 |
| 数据迁移 / 同步作业 | 长时任务 + 一致性校验是 `RIOT` 一类的战场。这里只做"选中这些键搬出去"(`DUMP`+`RESTORE` / RESP / JSONL) |
| `SYNC` / `PSYNC` | 客户端假装自己是从库会拉走整个数据集,一次误点就是一次生产事故 |
| Lua 脚本 IDE | 控制台的 `EVAL` 够用 |
| RedisJSON / Search 专用编辑器 | 目前经控制台可达;解码链里的 JSON 视图已覆盖大部分查看需求 |
| 隔离进程模式 | 宿主要向插件索取 Avalonia 控件,原生控件跨进程嵌入已被弃用 |

## 九、已知偏离(与界面设计稿相比)

设计稿上有、这一版**没有完全兑现**的地方,逐条记在这里而不是留给用户去发现:

| 偏离 | 现状 | 为什么 |
|---|---|---|
| Zstd / LZ4 / Snappy 解压 | 分段控件里**留着位置**,点不动,悬停写明"未内置" | 三者各需要一个额外的第三方依赖,而本仓库对随插件分发的依赖是逐个过许可证的(见 `Directory.Packages.props` 的注释)。内置的是 BCL 自带的 GZip / Deflate(zlib)/ Brotli,两个方向都做得到,因此**可编辑并写回** |
| Java 序列化 / Python pickle | 同上:认得出魔数,不假装解得开 | 两者都是对象图格式,做一半的解码器给出的是**看着像结果的错误结果** |
| 解码链作用范围 | 只对**字符串值**生效;成员表(hash/list/set/zset)的值不走这条链 | 成员的读写这一路仍是字符串;在它接上可逆表示之前,给成员表画一条不生效的解码工具条比不画更糟。成员表里含 `\xNN` 的二进制值目前**明确挡住写入**(见 §二) |
| 成员表分页的"上一页" | 记着每页起始游标回退,不能随机跳页 | `*SCAN` 的游标是单向的,服务端没有"第 37 页"。一个能点到任意页码的分页条,在游标分页上只能靠从头翻 —— 那正是 `KEYS` 式的灾难。(有序集合开了「分数区间」后走的是 `LIMIT offset count` 的索引分页,那条路可以随机跳,只是界面上仍只给前后翻) |
| 有序集合的排名 | `ZSCAN` 那条路上是**这一页里的名次**;开了「分数区间」走 `ZRANGEBYSCORE` 之后是**全局名次** | `ZSCAN` 不保证顺序,所以它给不出真名次;按分数区间读是索引分页,顺序由服务端保证 |
| 流的导出 | 只有 `DUMP + RESTORE` 这一条路,RESP / JSONL 会跳过并计入"已跳过" | 用 `XADD` 重放会拿到**新的条目 id**,那已经不是同一份数据 |
| 过滤条的「Aa」大小写开关 | **没做** | `MATCH` 永远区分大小写,服务端没有开关。要做只能把已扫到的键拉到客户端再筛一遍 —— 那会让"界面写着在过滤、实际只过滤了已扫到的那一批"成立,与本插件其余地方的口径矛盾 |
| 抽屉默认高度 300(设计稿 260) | 概览页的指标卡按设计稿是每张 3 条指标,真机 `INFO` 给得出 4 条 | 卡片因此要高出一行(约 119px)。仍按 260 开的话,要么裁掉第四条指标,要么把吞吐图挤到设计稿 134px 以下 —— 两者都比"默认多开 40px"糟。卡高不写死,由内容撑,`MinHeight` 保住设计稿的 96 |
| 吞吐图横轴刻度 `−40s / −20s / 现在`(设计稿 `−60s / −30s / 现在`) | 刻度由采样窗口算出来 | 采样窗口是 40 秒;设计稿上的 60 是示意值,照抄就是在界面上写一个假数字 |
